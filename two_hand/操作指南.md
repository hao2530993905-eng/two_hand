# 双臂协同完整操作指南

## 1. 系统对象与安全边界

| 名称 | 地址/设备 | 任务 |
|---|---|---|
| `second_hand` / 供件臂 | UR3 `192.168.1.5` + D435 `135622076024` | YOLO 识别白色工件、抓取、送到交接位、交接后返回观察位 |
| placement / 接件放置臂 | UR3 `192.168.1.4` + D455 `105322250617` | 固定位姿接件、深度差分识别红盒、放入目标槽 |
| D435 ROS 前缀 | `/d435/...` | 白色工件 RGB-D |
| D455 ROS 前缀 | `/camera/...` | 红盒 RGB-D |

坐标位姿统一采用 `[x, y, z, rx, ry, rz]`。除 `--target-pose` 的 XYZ
使用毫米外，其余 TCP XYZ 使用米，旋转向量使用弧度。速度和加速度沿用原项目
接口单位。

实机执行前必须做到：

- 两台 UR 均上电、松急停、处于可远程控制状态，没有其他 RTDE 控制客户端；
- 两台 Robotiq URCap/Socket 服务均可在端口 `63352` 访问；
- 两臂交接路径、返回路径和红盒路径已低速单独验证；
- 红盒、白色工件、相机和机械臂底座没有在标定后移动；
- 人员离开工作空间，急停可随时触达；首次协同建议把速度降到 `0.05`。

协同脚本直接通过 RTDE 控制两臂。正常任务不启动两个 UR ROS Driver，因为两个
Driver 默认都会创建同名 ROS 节点和 `base_link`，在同一个 ROS Master 中会冲突。
相机内部 TF、D435 眼在手标定和 D455 眼在外标定已由本工程独立保存。

## 6. 双臂流程时序

```text
供件臂：观察/识别 → 抓白件 → 抬升 → 交接位保持 ── 松爪 → 立即返回观察位
                                             ↑       └───────────────┐
接件臂：红盒规划 ───────────→ 交接位夹紧 → 等 put 时间              │
                                      松爪完成后等 wait 时间 → 撤回/抬升 → 红盒 → 释放
```

- `put_second_hand_time` 从接件臂夹爪闭合命令成功完成后开始计时；默认 `0.5 s`。
- 到时后供件臂执行松爪。松爪命令成功完成是第二段计时的零点。
- 供件臂松爪后立即在独立线程返回观察位姿。
- 接件臂从松爪完成起等待 `wait_second_hand`；默认 `0.5 s`，然后首先沿原路径撤回。
- 两臂后续运动并行。如果供件臂返回失败，主流程会报告错误；接件臂的既有阻塞
  运动调用不能在中途被软件安全地强行改写，因此现场急停仍是最高级保护。

这里的“供件臂初始位姿”明确指固定观察 TCP 位姿：

```text
[0.073120525, 0.463129264, 0.215102890, -1.284355, 1.309481, 1.488382]
```

如传入 `--observation-joints`，初次观察和交接后返回都会使用同一组关节角。

## 9. 参数详解

### 9.1 交接与执行

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `--put_second_hand_time` | `0.5` | 接件臂夹紧成功到供件臂开始松爪前的秒数；同时支持连字符写法 |
| `--wait_second_hand` | `0.5` | 供件臂松爪完成到接件臂开始撤回前的秒数；同时支持连字符写法 |
| `--execute` | 关闭 | 开启两臂和夹爪的真实控制；不加即干运行 |
| `--full-auto` | 关闭 | 跳过执行前唯一一次 `MOVE` 人工确认 |

计时参数不能为负。Robotiq 的“松爪完成”由夹爪通信返回成功定义，不是命令发出的
瞬间，因此 `wait_second_hand` 的物理含义明确且可重复。

## 10. 停止与异常处理

- 正常结束：主脚本会断开两台机械臂和夹爪；自动启动的深度节点随 ROS shutdown/
  Python 退出终止。
- 操作者取消：在输入 `MOVE` 前输入其他内容，机械臂不会进入连续协同段。
- 运行中异常：按 `Ctrl+C` 只请求软件停止，已经发给控制器的阻塞运动未必瞬时停止；
  发生碰撞风险应直接使用实体急停或保护停。
- 重启前确认没有残留控制进程：

```bash
ps -ef | grep -E 'two_hand_pick_and_place|depth_background_rect_detector' | grep -v grep
```

## 11. 常见故障

### 找不到 ROS Master

确认终端 1 的 `roscore` 正在运行，所有终端的 `ROS_MASTER_URI` 一致。

### 相机序列号不存在或 USB busy

```bash
rs-enumerate-devices | grep -E 'Name|Serial Number|Usb Type Descriptor'
```

关闭占用相机的旧进程，只保留 `start_cameras.sh` 启动的一组节点。
