`/home/sjh/WorkpiecePlacementUR3` 的设备层、动作层和任务层风格。当前版本已经

## 3. 单位与坐标约定

UR TCP 位姿格式统一为：

```text
[x, y, z, rx, ry, rz]
```

- `x/y/z`：米。
- `rx/ry/rz`：旋转向量，单位弧度，不是欧拉角。
- 关节角、关节速度、关节加速度：弧度制。
- `move_l_distance.py --distance` 沿 UR 控制器 `base` 的 Z 轴运动；正数上升，
  负数下降。
- D435 像素/深度转换、`d435_link` 到 `tool0`、再到 `base_link` 的计算尚未加入
  任务层。未来接视觉时必须使用本项目已保存的眼在手上标定，不能使用参考项目
  的 D455 眼在手外矩阵。

## 5. 控制模式不要混用

本项目有两条不同用途的机械臂链路：

1. `roslaunch d435_eye_on_hand robot.launch` 启动官方 UR ROS 驱动，用于机器人 TF、
   `/joint_states` 和手眼标定。
2. `complete_process` 脚本通过 `ur-rtde` 直接控制机械臂。

官方 ROS 驱动和 `ur-rtde` 会竞争 RTDE 控制寄存器。运行基础运动脚本前，停止
ROS 驱动及示教器中的 External Control 程序。若寄存器已经被占用，`UR_BASE`
会尝试通过 `30002` 端口发送 URScript；但检测到另一个机器人程序仍在运行时会
拒绝发出运动，避免覆盖现有程序。读取状态时使用 `connect_control=False`，不会
主动申请运动控制。

## 8. 基础运动

### 8.1 moveJ 到 TCP 位姿

脚本先检查逆运动学，再用 `moveJ` 移动到指定 TCP 位姿：


首次调试建议值，因此第一次应显式传入较低的 `--speed` 和 `--acc`。

### 8.2 沿 base Z 轴 moveL

第一次建议只上升 2 mm，以验证方向和连接：

```bash
cd /home/sjh/second_hand
python3 complete_process/utils/basic_move/move_l_distance.py \
  --host 192.168.1.5 \
  --distance 0.13 \
  --speed 0.01 \
  --acc 0.03 \
  --timeout 20
```

脚本先读取当前 TCP，将 Z 加上 `--distance`，打印起点和终点后执行直线运动。
负值会下降，确认下方净空前不要使用负值。

### 8.3 在 Python 中调用

```python
from complete_process.utils.base import UR_BASE

with UR_BASE("192.168.1.5") as robot:
    pose = robot.get_tcp_pose_or_raise()
    target = pose.copy()
    target[2] += 0.002
    result = robot.move_l(target, speed=0.01, acceleration=0.03, timeout_s=10.0)
    if not result.success:
        raise RuntimeError(result.message)
```

上下文退出时会断开连接，并尽力停止活动中的 servo/脚本运动。应用层仍需检查每个
`MotionResult.success`，超时或失败后不要继续执行下一步。

### 9.1 夹爪两指连线与 TCP 姿态标定

2026-08-26 在夹爪两指连线平行 UR 控制器 Base X、末端基本竖直向下时记录：

```text
TCP pose [mm, mm, mm, rad, rad, rad]:
[-109.581932, 298.818935, 176.858748, -1.789396, 2.572014, -0.018453]
wrist_3: 110.0 deg
```

姿态基准旋转向量为：

```text
GRIPPER_BASE_X_REFERENCE_ROTVEC = [-1.789396, 2.572014, -0.018453]
```

该姿态下，Base +X 表示到 TCP 坐标系中的单位向量为：

```text
finger_line_in_tcp = [-0.347687160, -0.937512857, 0.013538140]
```

投影到 TCP XY 平面后，夹爪两指连线相对 TCP +X 的安装偏角约为
`-110.347864°`。由于“两指连线”没有方向，`69.652136°` 是相差 180° 的等价
表示。若约定夹爪 Z 与 TCP Z 重合，可以使用以下近似旋转关系：

```text
tcp_R_gripper ≈ Rz(-110.347864°)
               [-0.347719027,  0.937598783, 0]
             = [-0.937598783, -0.347719027, 0]
               [ 0,            0,           1]
```

这里的 `wrist_3=110°` 只用于记录当时的关节分支，不能单独作为全局夹爪方向。
TCP 姿态由六个关节共同决定。控制时采用与参考项目相同的完整姿态基准方法：若
希望两指连线在 UR Base XY 平面内相对 +X 的角度为 `theta`，则

```text
base_R_tcp(theta) = Rz(theta) * base_R_tcp(reference)
```

两指连线在 `theta` 与 `theta + 180°` 时等价，应选择离当前 TCP 姿态更近的解，
避免腕关节无意义地旋转 180°。例如计算夹爪连线沿 Base X 的目标旋转向量：

```bash
cd /home/sjh/second_hand
python3 complete_process/utils/base/gripper_orientation.py \
  --target-angle-deg 0 \
  --nearby-rotvec -1.789396 2.572014 -0.018453
```

夹爪连线相对 Base X 逆时针 45°：

```bash
python3 complete_process/utils/base/gripper_orientation.py \
  --target-angle-deg 45 \
  --nearby-rotvec RX RY RZ
```

输出的 `[rx, ry, rz]` 可作为目标 TCP 姿态的后三项，但执行运动前仍必须结合安全
目标位置、逆运动学和关节限位检查。完整记录保存在
`complete_process/config/gripper_orientation.yaml`。当前这组数据只标定姿态关系；
若还需要夹爪中心相对 `tool0` 的 XYZ 偏移，必须另做 TCP 平移标定（例如固定尖点
四点法），不能由这一组姿态数据推出。

## 11. 白色矩形物品采集、训练与实时识别

### 11.1 人工旋转框采集

当前优先推荐人工拖框采集，不依赖深度差分：

```bash
cd /home/sjh/second_hand
./complete_process/utils/object_detective/start_manual_annotation.sh \
  --split train
```

旋转框采用两步鼠标操作：先沿物体长轴按住左键拖动，松开后横向移动调节宽度，
再单击左键确认。工具会自动启动或复用 ROS Master 和 D435 彩色相机，默认生成
`manual_white_rectangle_dataset` 下的 YOLO-OBB 数据。

| 操作 | 功能 |
| --- | --- |
| 第一次按住左键拖动 | 冻结画面，并指定物体长轴 |
| 松开后移动鼠标 | 调节倾斜框宽度 |
| 再单击一次左键 | 确认旋转框 |
| 右键点击框内 | 删除该框 |
| `Space` | 冻结或恢复实时画面 |
| `S` 或 `Enter` | 保存正样本、OBB 标签和预览图 |
| `N` | 保存空标签负样本 |
| `U` 或退格 | 撤销最后一个未保存框 |
| `C` | 清空当前帧的框 |
| `D` | 撤销本次运行最后保存的样本 |
| `Q` 或 `Esc` | 退出 |

需要采集验证集时：

```bash
./complete_process/utils/object_detective/start_manual_annotation.sh \
  --split val
```

当前人工数据集位于：

```text
complete_process/utils/object_detective/manual_white_rectangle_dataset/
├── dataset.yaml
├── images/{train,val}/
├── labels/{train,val}/
└── previews/{train,val}/
```

其中 `images` 是训练原图，`labels` 是归一化的 YOLO-OBB 四角标签，`previews`
仅供人工检查，不参与训练。一个标签的格式是：

```text
class_id x1 y1 x2 y2 x3 y3 x4 y4
```

当前唯一类别为 `0: white_rectangle`。训练集和验证集不要使用相邻连续帧；验证集
应改变物体位置、角度、距离、光照或背景。

常用参数：

| `_max_det` | 10 | 单帧最多保留的目标数量 |
| `_line_width` | 3 | 输出图中的旋转框线宽 |
| `_model` | 最佳模型路径 | 要加载的 `.pt` 权重 |
| `_image_topic` | `/d435/color/image_raw` | 输入 ROS 图像话题 |

```bash
rosnode list | grep white_rectangle_yolo_obb
```

### 11.4 白色矩形自动接近与抓取

任务脚本：

```text
complete_process/white_rectangle_pick.py
```

固定观察位姿为：

```text
[x, y, z, rx, ry, rz]
[0.030164653, 0.538836076, 0.237081963,
 -1.191308, 1.393567, 1.493523]
```

前三项已经从用户记录的毫米换算为米，后三项保持旋转向量弧度制。任务流程是：

1. `moveJ/IK` 到固定观察位姿并打开夹爪。
2. 机械臂保持在观察位姿，使用 YOLO11n-OBB 采集 12 帧稳定 RGB-D 目标；默认
   最多按 5 Hz 接受帧，并持续发布带框图像。
3. 使用 12 帧 OBB 中心像素和三维点的中位数确定最终中心点；每一帧的深度仍取
   对齐深度图中 OBB 中心附近有效深度的中位数。
4. 使用 D435 彩色内参反投影中心，并组合实时 RTDE TCP、保存的
   `tool0 <- d435_link` 手眼矩阵和 D435 内部光学 TF，得到 UR 控制器 Base 坐标。
5. 将夹爪两指连线固定为平行于 UR Base 坐标系 Z 轴。由于两指连线与夹爪接近轴
   必须正交，夹爪接近轴采用相机到目标方向在 Base XY 平面上的投影。
6. `moveJ/IK` 到目标中心前方 10 cm。
7. `moveL` 到目标中心前方 5 cm。
8. 以 `speed=255`、`force=255` 闭合 Robotiq 夹爪。
9. 读取抓取后的实际 TCP，使用 `moveL` 沿 Base 坐标系 `+Z` 上移 13 cm。
10. 使用 `moveJ/IK` 到最终点位
    `[-0.323390523, 0.120168609, 0.364210170, -1.489018, -1.057418, 1.446190]`，
    其中 XYZ 单位为米、旋转向量单位为弧度。

这里的“前方”定义为目标沿相机视线朝向相机的一侧。脚本默认只读当前 TCP、识别
并计算目标，不会运动，也不会操作夹爪。实际运动必须显式加入 `--execute`；默认
会在观察动作前和完整抓取动作前分别等待按一次回车，按 `Ctrl+C` 可取消。

终端 1 只启动 D435，不要同时启动 `robot.launch`，以免官方 UR ROS 驱动与
`ur-rtde` 竞争控制权：

```bash

source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
roslaunch d435_eye_on_hand d435_rgbd.launch
```

第一次必须先执行无运动试算。此时脚本使用机械臂当前实际 TCP 计算眼在手变换：

```bash
cd /home/sjh/second_hand
./complete_process/start_white_rectangle_pick.sh \
  --host 192.168.1.5 \
  --confidence 0.25 \
  --device cpu \
  --hold-preview
```

无运动试算时最好先用示教器把机械臂放到观察位姿附近，否则计算结果对应的是当前
相机姿态，而不是预定观察姿态。检查输出的中心像素、深度、UR Base 目标点、10 cm
预抓取位姿和 5 cm 抓取位姿。`--hold-preview` 会保留 ROS 调试话题，检查结束后在
脚本终端按 `Ctrl+C` 退出。

另开终端查看本次任务选中的 OBB 和中心点：

```bash
source /opt/ros/noetic/setup.bash
rqt_image_view /white_rectangle_pick/debug_image
```

确认无运动试算结果、工作空间和路径都安全后，使用完整执行命令：

```bash
cd /home/sjh/second_hand
./complete_process/start_white_rectangle_pick.sh \
  --execute \
  --host 192.168.1.5 \
  --gripper-port 63352 \
  --confidence 0.25 \
  --iou 0.45 \
  --imgsz 640 \
  --device cpu \
  --capture-frames 12 \
  --capture-fps 5 \
  --pregrasp-distance 0.10 \
  --grasp-distance 0.05 \
  --lift-distance 0.13 \
  --final-pose -0.323390523 0.120168609 0.364210170 -1.489018 -1.057418 1.446190 \
  --movej-speed 0.12 \
  --movej-acc 0.20 \
  --movel-speed 0.02 \
  --movel-acc 0.05 \
  --motion-timeout 30
```

`--capture-frames` 是移动前必须成功融合的稳定检测帧数，默认 `12`；旧参数
`--stable-samples` 仍可作为兼容别名。`--capture-fps` 是采集阶段最多接受的帧率，
默认 `5 Hz`，设为 `0` 表示接受相机送来的每一帧。降低帧率可以让 12 帧覆盖更长
时间，提高对短时检测抖动的抵抗能力；相应地要保证 `--input-timeout` 足够长。
任意一帧没有检测到目标或相邻中心移动超过 `--stability-px` 时，稳定帧计数会重新
开始，只有得到完整的 12 帧融合结果后机械臂才可能进入后续接近动作。

程序第一次停住时直接按回车，机械臂将前往观察位姿并打开夹爪。完成 12 帧融合、
打印预抓取、抓取、上移和最终位姿后，再次按回车执行余下完整动作。不再需要输入
`MOVE` 或 `GRASP`。

`--lift-distance` 单位为米，默认 `0.13`，方向固定为 Base 坐标系 `+Z`。
`--final-pose` 的前三项单位为米，后三项为旋转向量弧度。所有 `moveJ`/`moveJ/IK`
统一使用 `--movej-speed` 和 `--movej-acc`；所有 `moveL` 统一使用 `--movel-speed` 和
`--movel-acc`。

需要跳过全部回车确认、自动连续执行时，在上述命令末尾增加：

```bash
--full-auto
```

`--full-auto` 只有与 `--execute` 同时使用时才会产生运动。首次验证新点位或修改过
手眼矩阵、TCP、上移距离、最终位姿后，不要使用全自动模式。

若固定观察 TCP 位姿由控制器确认可达，但逆解仍返回空列表，应在示教器手动到达该
观察姿态，然后记录同一姿态下的实际关节角：

```bash
cd /home/sjh/second_hand
python3 complete_process/utils/base/read_current_pose.py \
  --host 192.168.1.5 \
  --precision 9 \
  --include-joints
```

把输出的 `joints_rad` 六个值传给抓取任务，即可用实测关节构型重复到达观察点，
避免固定 TCP 位姿的逆解分支歧义：

```bash
./complete_process/start_white_rectangle_pick.sh \
  --execute \
  --observation-joints Q1 Q2 Q3 Q4 Q5 Q6 \
  --host 192.168.1.5 \
  --gripper-port 63352
```

必须使用弧度制的 `joints_rad`，不能传入 `joints_deg`。当前项目的
`ur_rtde 1.6.0 + UR3 CB3` 组合中，`getInverseKinematicsHasSolution()` 会错误地
把当前实际 TCP 也报告为无解，因此底层封装已经改为直接读取
`getInverseKinematics()` 返回的六轴解。若该接口返回空列表，则需核对记录位姿时
使用的 Feature 是否为 `Base`，以及活动 TCP 是否与当前一致。

脚本还会读取控制器活动 TCP 偏移。当前实测是：

```text
[0, 0, 0.135, 0, 0, 0]
```

即 TCP 沿末端 Z 偏移 135 mm。计算眼在手相机外参时，脚本会先从实际 TCP 位姿中
消除这段偏移，恢复 `tool0` 位姿，再组合 `tool0 <- d435_link` 手眼标定；不能再把
活动 TCP 直接当作 `tool0`。

`--full-auto` 会跳过两次回车确认，不建议在尚未验证的场景使用。默认 UR Base
工作空间限制为 `X=[-0.45,0.45] m`、`Y=[0.05,0.75] m`、`Z=[0.03,0.65] m`；预抓取、
抓取、上移和最终位姿都必须在范围内。脚本只选择置信度最高的白色矩形；检测话题
和结果话题分别为：

```text
/white_rectangle_pick/debug_image
/white_rectangle_pick/result
```

该流程假设：机械臂当前活动 TCP 与手眼标定使用的 `tool0` 一致；夹爪接近轴与
TCP Z 重合；目标表面在 OBB 范围内近似平面。活动 TCP、相机安装或夹爪安装发生
变化后，不得继续使用旧标定结果。当前模型数据量很小，第一次真实执行必须降低
速度并在急停可触达的条件下单步确认。

若当前 RealSense 启动方式发布图像但没有发布
`d435_link -> d435_color_optical_frame`，脚本会自动使用 D435 URDF 的固定光学轴
旋转和 `0.015 m` 标称彩色相机偏移，并打印警告，不再直接退出。正常发布 TF 时
仍优先采用设备发布值。需要强制要求实时 TF 时可加入 `--require-camera-tf`；若有
单机实测的 D435 深度到彩色 Y 偏移，可用 `--d435-color-offset 米` 覆盖标称值。

完整参数、数据目录、标签格式、质量检查及 YOLO-OBB 训练命令见
[object_detective/README.md](complete_process/utils/object_detective/README.md)。

抓取任务时，目标点仍需从 D435 光学坐标转换到 `d435_link`，再通过已标定的
`tool0 <- d435_link` 和实时 `base_link <- tool0` 转到机器人基坐标，并继续保持
默认不运动、显式确认后才执行的边界。

## 12. 常见问题

### 提示 `rtde_control/rtde_receive is not installed`

在实际运行脚本的同一个 Python 环境里执行
`python3 -m pip install -r requirements-robot.txt`，然后重新做导入检查。

### 提示 RTDE input registers already in use

通常是官方 ROS 驱动、另一个 `ur-rtde` 进程或示教器程序正在占用控制寄存器。
停止占用者后重试。不要通过同时启动多个控制程序来绕开该错误。

### 提示 another robot program is running

URScript 兜底检测到了正在运行的程序并主动拒绝运动。停止现有程序，确认控制权
归属后再运行脚本。

### 运动超时

不要直接重复命令。先检查安全/保护停止、目标是否可达、速度参数、当前实际位姿
以及是否有另一个控制器。排除原因后，从只读测试重新开始。

### 夹爪连接失败

确认端口 `63352` 已由 Robotiq URCap 提供、夹爪已供电且没有其他客户端占用。
